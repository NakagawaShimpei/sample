# 講師用進行ガイド

---

## 1. 事前準備チェックリスト（Day1前までに完了）

### リポジトリ・環境

- [ ] GitHubなどにリポジトリを作成し、新人が `git clone` できる状態にする
- [ ] `npm start` でアプリが正常に起動することを自分のPCで確認する
  - ブラウザで http://localhost:3000 が開くこと
  - user / admin どちらでもログインできること
  - 会議室・デバイス一覧が表示されること
- [ ] `db.json` と `db-history.json` が初期状態になっていることを確認する
  - 研修前にテストで汚したデータは `git checkout db.json db-history.json` でリセット

### APIキー・アカウント

- [ ] 新人の人数分（2名）の Anthropic API キーを準備する
- [ ] キーの配布方法を決める（口頭・チャット・メモ用紙など）
- [ ] APIキーに利用上限が設定されているか確認する（研修中の過剰消費を防ぐ）

### 新人PCの準備

- [ ] 管理者権限の申請が完了していることをIT部門に確認する
  - Node.js・Git・VS Codeのインストールに必要
- [ ] 社内プロキシ設定が必要な場合は、設定手順を用意しておく

### 講師自身の準備

- [ ] `docs/setup.md` を読んで、環境構築の流れを頭に入れておく
- [ ] `docs/requirements.md` の「意図的に不完全にする箇所（A〜Q）」を確認する
  - 新人が気づかなかった場合のヒントとして使う
- [ ] `db-history.json` のデータパターンを確認する（Day2で説明するため）
  - 大会議室Aの少人数利用、第3会議室のキャンセル率高騰、水曜集中など
- [ ] 配布するリポジトリURLをメモしておく

## 2. Day 1（4/27）── 動かす・気づく

### アイスブレイク（30m）

**やること**
- 自己紹介（名前・所属・経歴など）
- 研修の目的・3日間の概要を説明する

**伝えるポイント**
- 「実装の量より、判断の質を見る研修」であることを最初に伝える
- 「AIに任せた点・自分で判断した点」のメモが最終的な成果物の一つになることを説明する
- 「完成させることが目的ではない」と明言する

---

### 環境構築①②（2H）

**やること**
- `docs/setup.md` の手順に沿って各自で進めてもらう
- 詰まっている人を個別にフォローする

**詰まりやすいポイントと対処**

| よくあるトラブル | 対処 |
|---|---|
| `npm install -g` で権限エラー | PowerShellを「管理者として実行」で開き直す |
| `claude --version` が通らない | PowerShellを再起動する。それでもダメなら `npm config get prefix` でPATHを確認 |
| APIキーの設定が反映されない | PowerShellを再起動してから `echo $env:ANTHROPIC_API_KEY` で確認 |
| 社内プロキシでダウンロードが失敗 | IT部門に確認。npmとgitの両方にプロキシ設定が必要 |

**目安：1時間経っても全員揃わない場合**
→ 先に進んでいる人に声をかけて、詰まっている人のサポートに回ってもらう

---

### アプリ起動（30m）

**やること**
- リポジトリURLを配布する
- `git clone → cd → npm install → npm start` を各自で実行してもらう
- ターミナルに `[API]` と `[APP]` の両方が表示されることを確認させる

**確認ポイント**
- `http://localhost:3000` でログイン画面が表示されること
- `user / user123` でログインして会議室一覧が出ること
- `admin / admin123` でログインして管理メニューが出ること

---

### アプリ理解（1H）

**やること**
- 「まずは自分で触ってみてください」と言って、各自に操作させる
- 「何ができるか・何が気になったか」を自分の言葉でメモに書かせる

**ファシリテーションのポイント**
- 答えを教えない。「どう思いますか？」と聞き返す
- 「使いにくいと感じた部分はありますか？」と適宜問いかける
- 意図的な不完全箇所（A〜Q）に自力で気づいているかを観察する

---

### 改善案検討（1H）

**やること**
- 各自の「改善したい点」リストを書かせる
- 優先順位をつけさせる（「今日実装するもの」を1つ決める）

**ファシリテーションのポイント**
- 「なぜそれを直したいと思ったか」を言語化させる
- 「AIに任せる部分」と「自分で判断する部分」を事前に考えさせる
- 4人で被っているテーマがあれば、あえて分散させるよう促す

---

### 初実装体験（1.5H）

**やること**
- 各自が選んだ改善案をClaude Codeで実装させる
- 実装後に「生成されたコードを読んでみる」時間を取らせる

**講師として伝えること**
- 「プロンプトは一度で完璧にしなくていい。対話しながら進めて」
- 「実装が終わったら、何が変わったかコードを読んで確認してみて」
- 「動いたとしても、なぜ動くのか理解することが大事」

**よくある詰まり**
- プロンプトが曖昧すぎてAIが的外れなコードを生成する
  → 「どのファイルの・どの部分を・どう変えたいか」を具体的に書くよう伝える

---

### 振り返りと共有（30m）

**やること**
- 各自に「今日やったこと・判断した点・残っている課題」を3〜5分で発表させる
- 引き継ぎメモ（Markdown等）に書いて保存させる

**引き継ぎメモに書かせる内容**
```
## AIに任せた点
- （例）フィルター機能のロジック全体

## 自分で判断した点・その理由
- （例）フィルターのUIはドロップダウンにした → 選択肢が固定のため
- （例）全件表示はやめてページネーションにした → 件数増加を想定して

## 残っている課題・次にやりたいこと
- （例）検索との組み合わせがまだ
- （例）モバイル対応が未実装

## 2週間後の自分へ
- （例）src/pages/RoomListPage.tsx の○行目あたりを変更した
```

### 新人へのアクション

- **特に課題は出さない**（2週間のブランクが意図的な仕掛け）
- Day1終了時に「次回5/11もよろしく」とだけ伝える

### 講師側の準備

- [ ] `db.json` の状態を確認する（新人が操作したデータが入っている場合、リセットするかどうか判断）
  - 基本はリセットしない（新人の変更が「引き継ぎ」の素材になる）
- [ ] Day2で使う「利用データ説明」の内容を整理する（後述）
- [ ] 新人が詰まりそうな箇所を予め想定しておく

## 4. Day 2（5/11）── 読む・改善する

### 思い出し（30m）

**やること**
- 「2週間前に何をやったか覚えていますか？」と問いかける
- アプリをもう一度触ってもらう
- 引き継ぎメモを読んでもらう

**ファシリテーションのポイント**
- 「覚えていない」「コードが読めない」という反応が出ることが正常
- 「それが今日の学びの出発点です」とポジティブに受け止める

---

### コードリーディング（1H）

**やること**
- 2週間前に自分が書いたコードを読み返させる
- 「なぜこう書いたか説明できますか？」と聞く

**引き出したいリアクション**
- 「コメントがなくてわからない」→ コメント・ドキュメントの重要性
- 「AIが生成したコードだから説明できない」→ 丸投げリスクの実感
- 「引き継ぎメモがあったから思い出せた」→ 設計書・メモの価値

---

### 実装計画（1H）

**やること**
- 残りの改善案リストを見直させる
- 「今日やる範囲」を決めさせる
- **Claude Codeに渡す前にプロンプトを先に書かせる**

**プロンプト設計の観点を伝える**
- 「どのファイルを変えるか」を指定しているか
- 「なぜそう変えたいか」を含んでいるか
- 「どんな動作を期待するか」が明確か

---

### 実装／コードリーディング（2H）

**やること**
- Claude Codeで実装させる
- 実装が終わったら生成されたコードを読ませる
- 「このコードをあなたは説明できますか？」と問いかける

---

### 利用データの説明（30m）★ここが重要

**やること**
- 「実はこのアプリに3ヶ月分の利用履歴データが入っています」と紹介する
- ブラウザで `http://localhost:3001/reservationHistory` を開いて見せる

**見せるデータパターンと問いかけ**

| データパターン | 見せ方 | 問いかけ |
|---|---|---|
| 大会議室Aに1〜2人の予約が多い | `?roomId=r004` でフィルター | 「定員30名の部屋を2名で使うのはなぜ？何か改善できる？」 |
| 第3会議室のキャンセル率が75% | `?roomId=r003` でフィルター | 「この部屋だけキャンセルが多い。原因は？フィードバック機能があったら？」 |
| 水曜日に予約が集中 | 日付を見て曜日を確認させる | 「忙しい曜日が見えると何ができる？」 |
| ヘッドセットの貸出が0件 | loanHistoryをdeviceIdで検索 | 「存在を知られてない？見つけにくい？」 |
| ノートPCの長期貸出（50〜72時間） | durationHoursを見せる | 「返却しない人への対応は？」 |

**伝えるメッセージ**
> 「このデータを分析する画面がないと、傾向に気づけません。
> データはあるのに活かせない、というのも改善余地の一つです。」

---

### データを活用した機能開発（2H）

**やること**
- データから気づいた「改善したい機能」を実装させる
- 実装後に「このデータがなければこの改善には気づかなかった」を振り返させる

---

### 振り返りと共有（30m）

- 判断メモを更新させる
- 「今日のコードリーディングで感じたこと」を全員に一言ずつ言わせる

---

## 5. Day 3（5/12）── 仕上げる・伝える

### 実装仕上げ（3H・昼含む）

**やること**
- 各自で作業。詰まっている人に声をかける
- 「完璧にしなくていい。発表でどう説明するかを考えて」と伝える

---

### 発表準備（2H）

**成果発表の構成を伝える**

```
① Before / After のデモ（実際にアプリを動かして見せる）
② 改善した内容の説明
③ 「AIに任せた点・自分が判断した点」の共有
④ やり残したこと・次にやりたいこと
```

- スライドは不要でも可。デモ＋メモで十分と伝える
- 発表時間は1人15分（発表10分＋質疑5分）

---

### 成果発表（1H）

**ファシリテーションのポイント**
- 実装の完成度ではなく、**判断の説明が明確かどうか**を評価軸にする
- 「なぜAIに任せたか」「なぜ自分で判断したか」を深掘りする質問をする
  - 「そこをAIに任せた理由は？」
  - 「他の選択肢も考えましたか？」
  - 「データを見てどう判断しましたか？」

---

### 全体振り返り（1.5H）

**ディスカッションのテーマ例**

1. 「AIを使ってみて、想像と違ったことは？」
2. 「2週間後に自分のコードを読んで、どう感じた？」
3. 「実務でAIを使うとしたら、どこで使いたい・使いたくない？」
4. 「判断メモを書いてみて、どうだった？」

**クロージングで伝えること**
- 「今日やったことは、実務でも同じプロセスです」
- 「AIは速くコードを書いてくれる。でも判断はあなたがしないといけない」
- 「今後もわからないことがあれば相談してください」
