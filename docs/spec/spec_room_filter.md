# 仕様書：会議室一覧 絞り込み機能

## 概要

会議室一覧画面（`/rooms`）にフィルター UI を追加し、会議室名・場所・キャパシティ・設備・本日の空き状況の各軸で表示を絞り込めるようにする。フィルター選択肢はデータに実在する値から動的に生成する。

## 詳細仕様

### 1. フィルター項目

| 項目 | UI種別 | 説明 |
|---|---|---|
| 会議室名 | テキスト入力（部分一致） | 入力文字を含む会議室名で絞り込む |
| 場所 | セレクトボックス | `rooms[].location` の一意な値を選択肢として表示 |
| キャパ | セレクトボックス | 定義済みの人数レンジから選択 |
| 設備 | セレクトボックス | `rooms[].equipment` を `,` で分割した一意な値を選択肢として表示 |
| 本日の空き状況 | セレクトボックス | 「空き」「予約あり」の固定値 |

---

### 2. フィルター選択肢の生成ルール

#### 場所（location）
- `rooms` 配列の `location` フィールドを重複排除し、文字列昇順でソートしたものを選択肢とする。
- 先頭に「すべて」を加え、デフォルト選択とする。

#### キャパシティ（capacity）
定義済みレンジを固定選択肢として使用する。

| 選択肢ラベル | 条件 |
|---|---|
| すべて | （デフォルト、絞り込みなし） |
| ～4名 | capacity <= 4 |
| 5～10名 | 5 <= capacity <= 10 |
| 11～20名 | 11 <= capacity <= 20 |
| 21名以上 | capacity >= 21 |

#### 設備（equipment）
- `rooms` 配列の `equipment` フィールドを `,` + 前後空白で分割する。
- 値が `"-"` の場合は「なし」として正規化する。
- 重複排除し、文字列昇順でソートしたものを選択肢とする。
- 先頭に「すべて」を加え、デフォルト選択とする。
- 選択した設備を **含む** 会議室に絞り込む。

#### 本日の空き状況
- 固定値: 「すべて」（デフォルト）、「空き」、「予約あり」

---

### 3. 絞り込みロジック

すべてのフィルターは **AND** 条件で適用する。

```
filteredRooms = rooms
  .filter(会議室名が入力文字を含む)
  .filter(場所が一致、または「すべて」)
  .filter(キャパがレンジ内、または「すべて」)
  .filter(設備を含む、または「すべて」)
  .filter(空き状況が一致、または「すべて」)
```

---

### 4. UI レイアウト

テーブルの上にフィルターエリアを配置する。

```
[ 会議室名: __________ ]  [ 場所: ▼ ]  [ キャパ: ▼ ]  [ 設備: ▼ ]  [ 空き状況: ▼ ]
[ リセットボタン ]
```

- フィルター変更時にリアルタイムで表示を更新する（ボタン操作不要）。
- フィルター適用後の件数を「N 件（全 M 件中）」の形式で表示する。
- 「リセット」ボタンですべてのフィルターを初期値に戻す。

---

### 5. 状態管理

コンポーネントローカルの state で管理する（DataContext への変更なし）。

```typescript
const [filterName, setFilterName] = useState('');
const [filterLocation, setFilterLocation] = useState('');
const [filterCapacity, setFilterCapacity] = useState('');
const [filterEquipment, setFilterEquipment] = useState('');
const [filterAvailability, setFilterAvailability] = useState('');
```

---

## 制約・前提

- フィルター状態はページ遷移時にリセットされる（セッション永続化は対象外）。
- `equipment` の値 `"-"` は「設備なし」を意味するため、設備フィルターで選択できるよう「なし」として表示する。
- フィルタリングはクライアントサイドのみで行い、API への追加リクエストは発生しない。
