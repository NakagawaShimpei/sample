## 1. 目的

| 習得目標 | 内容 |
|---|---|
| **AIと協働する判断力を養う** | Claude Codeを使いながら「AIに任せる部分」と「人が判断する部分」を自分の言葉で整理する |

## 2. 研修内容

### 研修の進め方

```
① 配布（講師）
   └─ サンプルアプリを新人のPCで起動できる状態にする

② 理解（新人）
   └─ アプリを実際に動かして「何ができるか」「何が足りないか」を自分の言葉でまとめる

③ 改善案の検討（新人）
   └─ UIの改善・機能の追加・バグの修正など、優先順位をつけてリストアップ

④ 実装（新人 × Claude Code）
   └─ Claude Codeを使って改善を実装。AIに任せる部分と自分で判断する部分を意識しながら進める

⑤ 振り返り・発表（新人）
   └─ 「何をAIに任せ・何を自分で判断したか」を言語化し、メンバーに共有する
```


### 題材：WE商品サンプルアプリ

講師が事前に作成した**会議室・デバイス管理/予約アプリ**を新人に配布する。  

#### 実際の商品を使わない理由
実際のWE商品ではなく、専用サンプルアプリを使う理由は以下の通り。

| 理由 | 詳細 |
|---|---|
| **クラウドDBの汚染・破壊リスク** | 開発環境とはいえクラウド上のDBを使っており、研修中の誤操作でデータを壊す・汚す可能性がある |
| **シークレット情報の漏洩リスク** | 本番・開発環境のAPIキーや接続情報がコード内に含まれており、新人に扱わせるのはセキュリティ上危険 |
| **環境構築の複雑さ** | 実商品の開発環境は依存関係や設定項目が多く、限られた研修時間内に全員が揃えるのが難しい |

サンプルアプリはこれらのリスクをすべて排除した、**研修専用の安全な環境**担っている。


#### アプリでできること（主要機能

| 機能 | 利用者 | 管理者 |
|---|---|---|
| 会議室の一覧・予約・キャンセル | ✓ | ✓ |
| デバイスの一覧・貸出・返却 | ✓ | ✓ |
| 会議室・デバイス・ユーザーの登録・削除 | | ✓ |

また、過去3ヶ月分の利用履歴データも組み込んでおり、  
データの傾向からどういう改善が可能かを考える体験もできる。


## 3. 研修の方針・アプローチ

### 基本方針

> **「AIを使って素早く動かし、人として判断する経験を積む」**

Claude Codeを使えば実装は短時間で終わる。  
その分の時間を、**コードを読む・理由を言語化する・判断を記録する**に充てる。

### 研修の仕掛け

**① 意図的に不完全なサンプルアプリ**

講師が用意するサンプルアプリには、UIの古さ・機能の欠落・セキュリティ上の課題などを意図的に仕込んでいる。新人が自分で「改善すべき点」を発見する体験を設計。

**② 2週間の空白期間を活用**

Day1（4/27）とDay2（5/11）の間に2週間空く。
「2週間前に自分（とAI）が書いたコードを読み解く」という疑似的な引き継ぎ体験を通じ、**ドキュメントの重要性**と**AIへの丸投げリスク**を実感させる。

**③ 判断メモの作成**

実装のたびに「AIに任せた点・自分が判断した点・その理由」を記録する。  
発表時にこのメモを共有することで、**技術的な成果だけでなく思考プロセスを評価**できる構成にする。
