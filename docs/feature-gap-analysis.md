# Workplace Resource Manager — 追加・修正機能リスト

> **優先度の方針:** 経営層・現場社員の視点を重視。IT部門の要件は土台が整ってから。

---

## Phase 1 — 今すぐ直す（壊れている・使えない）

### バグ修正

| # | 機能 | 問題 | 対応 |
|---|------|------|------|
| 1 | **ログアウト機能** | ログアウトボタンが存在しない。セッションを終了する手段がない | Layout にログアウトボタン追加、AuthContext に logout() を実装 |
| 2 | **予約者名が保存されない** | フォームの「予約者名」欄を編集しても無視され、常に username が保存される | `reservedBy: currentUser?.username` を `reservedBy` state の値に修正 |
| 3 | **重複予約が作れる** | 同じ会議室・同じ日時で二重予約を防ぐチェックがない | 送信前に既存予約と時間帯が重複しないか検証 |
| 4 | **パスワードが画面に表示される** | ユーザー一覧でパスワードが平文表示。入力フォームも `type="text"` | 一覧はマスキング表示、フォームは `type="password"` に変更 |

### バリデーション追加

| # | 機能 | 問題 | 対応 |
|---|------|------|------|
| 5 | **終了時刻のチェック** | 開始より前の終了時刻で予約が作れる | `endTime > startTime` のバリデーションを追加 |
| 6 | **定員超えのチェック** | 部屋の定員を超えた人数で予約できる | `attendeeCount <= room.capacity` のチェックを追加 |
| 7 | **過去日付のチェック** | 過去の日付で予約が作れる | 今日以降の日付のみ選択可能にする |
| 8 | **重複ユーザー名のチェック** | 同じユーザー名で複数アカウントが作れ、ログインが壊れる | 登録前に username の重複確認を追加 |

## Phase 2 — 短期（現場社員が使いやすくなる）

| # | 機能 | 内容 | 備考 |
|---|------|------|------|
| 9 | **会議室の絞り込み検索** | 人数・設備・キーワードで会議室を絞り込み。空き会議室のみ表示するフィルタも追加 | フロントのみで完結、実装コスト低 |
| 10 | **時間別の空き状況** | 選択した日付で各会議室が何時〜何時まで埋まっているか一覧表示。タイムライン形式が理想 | 現状「今日空きかどうか」しか見えない |
| 11 | **予約の編集** | キャンセル → 再予約の手間をなくす。既存予約の日時・人数・会議名を変更できるようにする | API に PATCH エンドポイントが必要 |
| 12 | **マイページ（自分の予約・貸出を1画面で確認）** | 自分の予約と機器貸出を集約して表示 | 現状は別々のページを行き来する必要がある |

---

## Phase 3 — 中期（経営層が喜ぶ・現場の快適性向上）

| # | 機能 | 内容 | 備考 |
|---|------|------|------|
| 13 | **稼働率ダッシュボード** | 会議室・機器の稼働率を棒グラフ・数値で表示。期間指定に対応 | `db-history.json` の履歴データを活用できる |
| 14 | **空き時間ヒートマップ** | 曜日・時間帯ごとの混雑度を色で可視化。「火曜14時が一番混む」が一目でわかる | 経営層の投資判断材料になる |
| 15 | **過剰・不足アラート** | 稼働率が閾値（90%超 / 10%未満）を超えた設備をアラート表示 | 設備購入・削減の根拠に |
| 16 | **機器貸出統計** | 機器種別ごとの貸出頻度・平均貸出日数を集計 | どの機器が足りていないか把握できる |
| 17 | **カレンダービュー** | 会議室ごとの予約を週・月単位でカレンダー表示 | Phase 2 の時間別表示の発展版 |
| 18 | **レポートエクスポート** | 稼働率・貸出統計を CSV / PDF で出力 | 経営会議の資料として使える |

---

## Phase 4 — 長期（IT基盤を固める）

| # | 機能 | 内容 |
|---|------|------|
| 19 | **機器メンテナンス管理** | `status: 'maintenance'` は型に定義済みだが、変更UIがない。管理画面から変更できるようにする |
| 20 | **操作ログ** | 予約・貸出・ユーザー追加などの操作を記録。管理者が閲覧できる監査ログ画面を追加 |
| 21 | **ロール拡張** | `user / dept-admin / admin` の3段階に拡張。部門管理者が自部門のリソースのみ管理できる |
| 22 | **SSO / カレンダー連携** | Google Calendar 等との同期（モックAPI限界のため将来対応） |
