## 1. 定期予約（繰り返し予約）機能

### 1.1 背景・目的

利用履歴 rh068〜rh075 の 8件がすべて同一パターン（毎週水曜 10:00〜11:00）で手動登録されていた。繰り返し予約機能を提供することで、毎週の手動作業を排除し、登録ミスや登録漏れを防ぐ。

### 1.2 ユーザーストーリー

| ID | ロール | ストーリー |
|----|--------|-----------|
| US-RR-01 | 一般ユーザー | 定例会議を一度の操作で複数週分登録したい |
| US-RR-02 | 一般ユーザー | 定期予約の一部だけ（特定日）をキャンセルしたい |
| US-RR-03 | 一般ユーザー | 定期予約をまとめてすべてキャンセルしたい |
| US-RR-04 | 管理者 | 定期予約グループを予約一覧で把握したい |

### 1.3 機能要件

#### FR-RR-01: 予約フォームの時間設定

- 開始時刻・終了時刻・会議時間（分）の3項目を連動させる
  - 開始時刻を変更すると、会議時間を維持したまま終了時刻が自動計算される
  - 終了時刻を変更すると、開始〜終了時刻から会議時間が自動計算される
  - 会議時間を変更すると、開始時刻を維持したまま終了時刻が自動計算される
- 会議時間のプリセット（15分・30分・45分・1時間・1.5時間・2時間・2.5時間・3時間・3.5時間・4時間・5時間・6時間・7時間・8時間）を選択肢として提供する

#### FR-RR-02: 繰り返し設定の入力

- 予約フォームに「繰り返し設定」チェックボックスを追加する
- チェック時、パターン設定と期間設定の2つのブロックを展開する

**パターン設定（4種類）:**

| パターン | 設定項目 |
|----------|---------|
| 毎日 | 間隔（X日ごと）または「全ての平日（月〜金）」のいずれかを選択 |
| 毎週 | 間隔（X週ごと）＋ 繰り返す曜日（複数選択可） |
| 毎月 | 間隔（Xカ月ごと）＋ 「何日」（月の特定日）または「第N曜日」のいずれかを選択 |
| 毎年 | 間隔（X年ごと）＋ 月の選択 ＋ 「何日」または「第N曜日」のいずれかを選択 |

- 第N曜日の N は「第1・第2・第3・第4・最終（第5）」から選択可能

**期間設定（3種類）:**

| 終了条件 | 設定項目 |
|----------|---------|
| 終了日を指定 | 日付入力（開始日以降） |
| 反復回数を指定 | 整数入力（2以上） |
| 終了日未定 | 上限なし（内部上限52回を自動適用） |

#### FR-RR-03: 定期予約の一括作成

- フォーム送信時、指定されたパターンに従い該当日程の予約レコードを一括作成する
- 作成されたすべての予約に同一の `recurringGroupId`（UUID形式）を付与する
- 各予約に `recurringPattern`（日本語のパターン説明文字列）を付与する
- 重複チェックは各日程に対して個別実行する
- 特定日程で重複が発生した場合: その日程をスキップし、他の日程は登録する
- 登録完了後、作成件数とスキップ件数をユーザーに通知する

#### FR-RR-04: 予約一覧での識別表示

- 定期予約（`recurringGroupId` 持ち）には繰り返しパターン説明のバッジを表示する
- バッジのツールチップにグループID（`recurringGroupId`）を表示する

#### FR-RR-05: キャンセル操作の拡張

- 定期予約の「キャンセル」ボタンクリック時、以下の2択をモーダルで提示する:
  - 「この予約のみキャンセル」: 選択した1件だけ削除
  - 「同グループをすべてキャンセル」: 同じ `recurringGroupId` を持つすべての予約を一括削除
- 単発予約のキャンセルは従来通り確認ダイアログのみ

### 1.4 制約・非機能要件

| 項目 | 内容 |
|------|------|
| 終了日未定時の上限 | 52回（約1年分） |
| 最小繰り返し回数指定 | 2回以上 |
| パターン変更 | 登録後の繰り返しパターン変更は不可 |
| 個別編集 | 定期グループ内の個別予約の編集は対象外（現行の予約編集機能なし） |
| 毎日（平日のみ）の最大生成 | 最大10,000回のイテレーション制限（内部安全キャップ） |

## 2. デバイス返却リマインダー・延滞アラート

### 2.1 背景・目的

貸出履歴に週末をまたぐ長時間貸出が 3件確認された（最大 72時間）。他ユーザーの業務影響を防ぐため、返却予定日時の設定と期限超過時のアラート機能を追加する。

### 2.2 ユーザーストーリー

| ID | ロール | ストーリー |
|----|--------|-----------|
| US-DR-01 | 一般ユーザー | デバイス借用時に返却予定日時を設定したい |
| US-DR-02 | 一般ユーザー | 自分が借りているデバイスの残り時間を確認したい |
| US-DR-03 | 一般ユーザー | 返却期限超過時に画面上で通知を受けたい |
| US-DR-04 | 管理者 | 延滞中・長時間貸出中のデバイス一覧を確認したい |
| US-DR-05 | 管理者 | 各貸出の経過時間と状態をひと目で把握したい |

### 2.3 機能要件

#### FR-DR-01: 返却予定日時の設定

- デバイス一覧ページの「貸出」ボタンクリック時、返却予定日時の入力フォームを表示する（任意入力）
- 入力された日時は `Loan.expectedReturnAt` フィールドに ISO 8601 形式で保存する
- 未入力の場合は `expectedReturnAt` なしで登録する

#### FR-DR-02: アラート状態の判定基準

| 状態 | 条件 |
|------|------|
| 延滞中 (overdue) | `expectedReturnAt` が設定されており、現在時刻が期限を過ぎている |
| まもなく期限 (warning) | `expectedReturnAt` が設定されており、期限まで1時間以内 |
| 長時間貸出中 (longDuration) | `expectedReturnAt` が未設定で、貸出開始から8時間以上経過 |
| 通常 (normal) | 上記以外 |

- 判定はクライアントサイドで `getLoanAlertInfo()` 関数が担う（定数 `LONG_LOAN_HOURS = 8`）

#### FR-DR-03: デバイス一覧でのアラート表示

自分が借りているデバイス行に以下の状態バッジを表示する:

| 状態 | バッジ表示 | 色 |
|------|------------|----|
| 延滞中 | 「延滞中 (+Xh Xm)」 | 赤 |
| まもなく期限 | 「まもなく期限 (残Xm)」 | 黄 |
| 長時間貸出中 | 「長時間貸出中 (Xh経過)」 | 黄 |
| 通常 | （なし） | — |

#### FR-DR-04: 貸出一覧でのアラート表示（管理者）

- 各貸出行に状態バッジを表示する（FR-DR-03 と同じ基準）
- ページ上部に「延滞中: X件 / 長時間貸出（8h超）: Y件」のサマリーを表示する
- 「貸出日時」列に経過時間（時間・分）を併記する
- 「返却予定」列を追加し、`expectedReturnAt` を表示する

#### FR-DR-05: グローバルバナーアラート

- ログイン中のすべてのページで、自分が借りているデバイスに延滞があればヘッダー下にバナーを表示する
- バナーには延滞デバイス名を列挙し、件数を表示する
- 「×」ボタンでバナーを非表示にできる（ページ遷移で再表示される）

### 2.4 制約・非機能要件

| 項目 | 内容 |
|------|------|
| 長時間判定閾値 | 8時間（定数 `LONG_LOAN_HOURS` で管理） |
| 通知手段 | アプリ内のみ（メール・外部通知は対象外） |
| アラート評価タイミング | ページ表示時にクライアントサイドで評価 |
| 自動ポーリング | なし（手動リロードで最新化） |

## 3. 通知ベル

### 3.1 背景・目的

FR-DR-05 のグローバルバナーは延滞のみを対象としており、「まもなく期限」「長時間貸出」の状態はユーザーが該当ページを開かないと把握できない。ヘッダーに通知ベルを設け、すべてのアラート状態をアプリ全体で気づきやすくする。

### 3.2 ユーザーストーリー

| ID | ロール | ストーリー |
|----|--------|-----------|
| US-NB-01 | 一般ユーザー | 自分のデバイス貸出のアラートをどのページからでも確認したい |
| US-NB-02 | 管理者 | 全ユーザーの貸出アラートを一か所で確認したい |
| US-NB-03 | 全ユーザー | 未読の通知がある場合はアイコンで気づけるようにしたい |
| US-NB-04 | 全ユーザー | 既読にした通知は次回から表示を変えたい |

### 3.3 機能要件

#### FR-NB-01: 通知ベルアイコンの表示

- ヘッダーのログイン中ユーザー名の左に、ベル形のアイコンボタンを表示する
- 未読の通知がある場合、アイコンの右上に赤いバッジで未読件数を表示する
- 99件を超える場合は「99+」と表示する

#### FR-NB-02: 通知の生成ルール

貸出のアラート状態を評価し、以下の条件で通知を生成する:

| アラート状態 | 生成される通知 | 重大度 |
|-------------|---------------|--------|
| 延滞中 (overdue) | 「【延滞】{デバイス名} の返却期限を {超過時間} 超過しています。」 | error（赤） |
| まもなく期限 (warning) | 「【まもなく期限】{デバイス名} の返却期限まで残り {残り分} です。」 | warning（黄） |
| 長時間貸出中 (longDuration) | 「【長時間貸出】{デバイス名} を {経過時間} 借り続けています（借用者: {ユーザー名}）。」 | warning（黄） |

- 通知の識別キー（`loanKey`）は `{貸出ID}-alert-{状態}` 形式とし、同じキーの通知は重複生成しない
- 貸出が返却されると、その貸出に紐づく通知は自動で削除される

#### FR-NB-03: 通知の対象範囲

| ロール | 対象となる貸出 |
|--------|--------------|
| 一般ユーザー | 自分が借りている貸出のみ |
| 管理者 | 全ユーザーの貸出 |

#### FR-NB-04: 通知ドロップダウンパネル

- ベルアイコンクリックで通知一覧パネルを開閉する
- パネルには通知を新しい順（降順）に最大表示する
- 各通知には本文・生成日時・重大度（色）を表示する
- 通知クリックで既読にする
- 「全て既読にする」ボタンでまとめて既読にできる
- パネル外クリックでパネルを閉じる

#### FR-NB-05: 通知の永続化

- 通知は `localStorage` にユーザーごと（キー: `we-notifications-{username}`）に保存する
- ページリロード・タブ再開後も通知と既読状態を保持する

### 3.4 制約・非機能要件

| 項目 | 内容 |
|------|------|
| 通知生成タイミング | ページ表示時・貸出データ変化時にクライアントサイドで評価 |
| 自動ポーリング | なし（手動リロードで最新化） |
| 通知の削除 | 自動削除（貸出消滅時のみ）。手動削除は対象外 |
| サーバー側連携 | なし（クライアントサイドのみで完結） |
| 他のアラートとの関係 | グローバルバナー（延滞）と併用する。通知ベルはより広い状態を対象とする |
