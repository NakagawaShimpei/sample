# 大手企業への販売に向けた重要観点

職場リソース管理アプリを大手企業に採用してもらうために、意思決定に関わる三者の観点から整理する。

---

## 1. 経営層（CxO・役員）の観点

経営層が意思決定する際に重視するのは「投資対効果」「リスク」「競争優位性」の三点。

### 投資対効果（ROI）
- **コスト削減の定量化**: 会議室ダブルブッキング防止、デバイス紛失・管理コスト削減、管理者工数削減の数値を示す
- **導入コスト vs 運用コスト**: ライセンス費用・カスタマイズ費用・保守費用の透明な提示
- **回収期間の明示**: 「何ヶ月で元が取れるか」を具体的なシナリオで説明できること

### コンプライアンス・ガバナンス
- **監査ログ**: 誰がいつ何をしたかを追跡できる操作履歴（現状未実装）
- **個人情報保護**: パスワード等の機密情報の適切な管理（現状 CRITICAL 問題あり）
- **セキュリティポリシー準拠**: ISO 27001、SOC 2 等の認証・準拠状況
- **データ主権**: データの保管場所・国内サーバー対応の有無

### 戦略的価値
- **将来の拡張性**: 拠点増加・ユーザー数増加に対応できるスケーラビリティ
- **ベンダーロックインリスク**: 移行コスト・データエクスポートの容易さ
- **サポート継続性**: 提供元企業の安定性・サポート期間の保証

### 現状のギャップ
| 観点 | 現状 | 必要な対応 |
|------|------|-----------|
| 監査ログ | なし | 全操作の記録・エクスポート機能 |
| セキュリティ認証 | なし | ISO 27001 等の取得 |
| SLA | なし | 稼働率保証・障害対応時間の定義 |
| 契約・保証 | なし | 利用規約・免責範囲の整備 |

## 2. IT部門（情報システム部・セキュリティ担当）の観点

IT部門は「技術的安全性」「既存システムとの統合」「運用負荷」を中心に評価する。最も厳しい審査者であり、ここを通過できないと導入は進まない。

### セキュリティ（最優先）
現状のアプリには製品化に不適切なセキュリティ欠陥が複数存在する。詳細は OVERVIEW.md 参照。

**最低限必要な対応（現状 CRITICAL）:**
- サーバー側認証・認可の実装（現状クライアント側のみ）
- パスワードのハッシュ化（現状平文保存）
- APIへの認証ミドルウェア（現状無認証でCRUD可能）
- HTTPS の強制
- セッション管理の強化（有効期限・ログアウト）

**追加で求められること:**
- 多要素認証（MFA）対応
- シングルサインオン（SSO / SAML / OIDC）対応
- ペネトレーションテスト実施と報告書の提出
- 脆弱性スキャン（SAST / DAST）の継続実施

### 既存システムとの統合
- **Active Directory / LDAP 連携**: 社員が既存の社内アカウントでログインできること（別途ユーザー管理不要）
- **グループウェア連携**: Outlook / Google Calendar との予約同期
- **資産管理システム連携**: デバイス管理データを既存台帳と同期
- **シングルサインオン**: 他社内システムとのSSO統合

### 運用・保守
- **オンプレミス / クラウド選択**: 自社データセンターへのインストールが可能か
- **バックアップ・リストア**: データの定期バックアップと復旧手順の整備
- **アップデート管理**: セキュリティパッチの適用方法・ダウンタイムの有無
- **ロールベースアクセス制御の柔軟性**: 現状は `user` / `admin` の2段階のみ（部門単位・承認フロー等が必要）
- **監視・アラート**: サーバー異常・不正アクセスの検知通知

### インフラ要件の明確化
- 必要スペック（CPU・メモリ・ストレージ）の提示
- 同時接続ユーザー数の上限と負荷テスト結果
- データ保持期間とストレージ増加の見積もり

### 現状のギャップ
| 観点 | 現状 | 必要な対応 |
|------|------|-----------|
| 認証方式 | 独自 | SSO / SAML / LDAP 対応 |
| MFA | なし | TOTP / SMS 認証 |
| 権限粒度 | 2段階のみ | 部門・チーム単位のロール |
| ログ | なし | アクセスログ・操作ログ |
| バックアップ | なし | 自動バックアップ・手順整備 |
| 負荷テスト | なし | 同時接続数・性能指標の提示 |

## 3. 現場社員の観点

現場社員は直接の利用者であり、**使いやすさと業務への馴染みやすさ**が採用後の定着率を左右する。経営層がGoサインを出しても現場に拒否されると活用されないまま終わる。

### 使いやすさ・UX
- **直感的な操作**: 初めてでもマニュアルなしで使えるUI
- **操作ステップ数の少なさ**: 予約完了まで何画面・何クリックか（現状は比較的シンプル）
- **エラーメッセージの分かりやすさ**: 何が間違っていて何をすればいいか明確に

### 実用的な機能の充実
現状の機能では大手企業の日常業務には不足が多い：

| 現状にない機能 | ユーザーが必要とする理由 |
|-------------|-------------------|
| 会議室の空き状況カレンダー表示 | 一目で空き枠を確認したい |
| 繰り返し予約（週次・隔週） | 定例会議を毎回登録するのは手間 |
| 予約変更機能 | キャンセル→再登録の二度手間をなくしたい |
| 予約リマインダー通知 | 当日忘れを防ぎたい |
| 会議室の写真・図面表示 | どの部屋か視覚的に確認したい |
| デバイスの予約（事前確保） | 当日に貸出中だったを防ぎたい |
| スマートフォン対応（レスポンシブ） | 外出先・移動中に予約確認したい |
| 検索・絞り込み機能 | 設備・収容人数・場所で絞りたい |

### 信頼性・パフォーマンス
- **表示速度**: 一覧表示が遅いとストレスになる（現状は全件取得のため大規模データで問題が出る）
- **予約の確実性**: 二重予約が発生しないこと（現状バリデーションが不十分）
- **オフライン対応**: ネットワーク断時の挙動が明確であること

### サポート・学習コスト
- **日本語対応**: UI・マニュアル・サポートがすべて日本語（現状対応済み）
- **ヘルプ・チュートリアル**: 操作に迷ったときの手引き
- **問い合わせ窓口**: 困ったときに人に聞ける体制

## 総括：販売に向けたロードマップ

### フェーズ1 — 製品化の最低条件（セキュリティ基盤）
> これがないと IT部門の審査を通らない

1. サーバー側認証・認可の実装（JWT + ミドルウェア）
2. パスワードのbcryptハッシュ化
3. APIからのパスワード除外
4. HTTPS強制
5. セッション管理（タイムアウト・ログアウト）
6. 操作ログ・監査ログの実装

### フェーズ2 — エンタープライズ対応
> 大手企業の調達基準を満たすために必要

7. SSO / SAML / LDAP 連携
8. 多要素認証（MFA）
9. ロールの多段階化（部門・承認フロー）
10. バックアップ・リストア手順の整備
11. 負荷テスト実施と性能指標の公開
12. SLA・サポート体制の整備

### フェーズ3 — 現場定着のための機能拡充
> ユーザーが「使い続けたい」と思う製品にするために必要

13. カレンダー表示（週次・月次ビュー）
14. 繰り返し予約・予約変更
15. 通知・リマインダー機能
16. スマートフォン対応（レスポンシブデザイン）
17. 検索・フィルタリング強化
18. グループウェア（Outlook / Google Calendar）連携

---

## 意思決定者別の訴求ポイントまとめ

| 観点 | 最も響くメッセージ | 現状のギャップ |
|------|-----------------|-------------|
| 経営層 | コスト削減・ROI・コンプライアンス | 定量データなし・監査機能なし |
| IT部門 | セキュリティ・統合・運用負荷軽減 | 認証・認可・ログが未整備 |
| 現場社員 | 使いやすさ・業務効率化・信頼性 | カレンダー表示・繰り返し予約等が未実装 |
