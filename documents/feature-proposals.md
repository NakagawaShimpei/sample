# 利用履歴に基づく機能追加提案

作成日: 2026-05-11  
分析元: `backend/data/db-history.json`（予約履歴 97件、貸出履歴 43件）

---

## 提案一覧と優先順位

| 優先度 | 機能名 |
|--------|--------|
| ★★★ 高 | 定期予約（繰り返し予約）機能 |
| ★★★ 高 | デバイス返却リマインダー・延滞アラート |
| ★★☆ 中 | キャンセル率異常検知・管理者通知 |
| ★★☆ 中 | 予約時の混雑状況表示と代替時間帯の提案 |
| ★★☆ 中 | 会議種別に応じたデバイス推奨 |
| ★☆☆ 低 | 利用レポートのエクスポート（CSV） |
| ★☆☆ 低 | 予約キャンセル待ちリスト |

## 詳細

---

### 1. 定期予約（繰り返し予約）機能 ★★★

**根拠となるデータ**  
rh068〜rh075 の 8件がすべて同一パターン（sato / r007 / 週次定例 / 毎週水曜 10:00〜11:00 / 参加者4名）。  
同じ内容の予約が 2026-02-25 から 2026-04-15 まで毎週手動で登録されており、繰り返し予約の需要が明確に存在する。

**提案内容**  
- 予約登録画面に「繰り返し設定」オプションを追加（毎週・隔週・毎月など）
- 繰り返し終了日または回数を指定可能にする
- 繰り返しグループ単位でのキャンセル（一括・個別選択）に対応する

**優先度が高い理由**  
利用履歴から需要が直接確認できる機能であり、繰り返し予約がなければ毎週の手動登録が続く。実装コストに対してユーザーの手間削減効果が大きい。

---

### 2. デバイス返却リマインダー・延滞アラート ★★★

**根拠となるデータ**  
貸出履歴に週末をまたぐ長時間貸出が 3件確認された。

| ID    | 借用者   | 貸出時間 | 期間 |
|-------|----------|----------|------|
| lh031 | suzuki   | 50時間   | 土〜月 |
| lh032 | user     | 58時間   | 金〜日 |
| lh033 | nakagawa | 72時間   | 木〜日 |

通常の業務利用（3〜8時間）と比較して明らかに逸脱しており、返却忘れの可能性が高い。  
また lh021 で `durationHours = 0`（借用・返却日時が同一）というデータ品質の問題も発生している。

**提案内容**  
- 貸出開始から設定した時間（例: 8時間）を超えた場合、借用者にアプリ内通知またはメール通知を送る
- 管理者画面に「長時間貸出中デバイス一覧」を表示する
- 貸出登録時の返却予定日時の入力を任意で追加し、予定時刻を過ぎたら自動アラートを出す

**優先度が高い理由**  
デバイスの長期占有は他ユーザーの業務に直接影響する。履歴データから実害の発生が確認されており、仕組みで防ぐ必要性が高い。

---

### 3. キャンセル率異常検知・管理者通知 ★★☆

**根拠となるデータ**  
rh076〜rh083 の 8件はすべて r003 / 13:00〜14:00 の枠であり、うち 6件（75%）がキャンセル。  
全体のキャンセル率 22% と比較して著しく高く、特定の部屋・時間帯に問題（設備不良・立地・アクセスなど）がある可能性がある。

**提案内容**  
- 部屋ごとのキャンセル率を週次または月次で集計し、閾値（例: 50%超）を超えた場合に管理者へ通知する
- ダッシュボードの「部屋別キャンセル率」チャートに閾値ラインを表示する
- キャンセル時に任意でキャンセル理由を入力できるフォームを設け、傾向を収集する

**優先度が中の理由**  
問題の存在は示唆されるが、キャンセル理由がデータに含まれないため原因特定には追加情報が必要。まず理由収集の仕組みを作ることが先決。

---

### 4. 予約時の混雑状況表示と代替時間帯の提案 ★★☆

**根拠となるデータ**  
- 10:00 開始が最多スロット（全体の最人気）
- r004 が最多利用（20件）で 1on1 に集中
- 09:00〜11:00 の午前と 13:00〜14:00 の午後初めに予約が集中している

**提案内容**  
- 予約フォームで日時を選択した際、その時間帯の混雑度（過去の予約件数ベース）をヒートマップや「混雑」「空き」のラベルで表示する
- 選択した時間帯が混雑している場合、空き時間帯を候補として提示する
- 「1on1 でよく使われている部屋」など用途別の推奨部屋を表示する

**優先度が中の理由**  
ユーザー体験向上には有効だが、現在は予約の重複チェック（バグ修正済み）が最低限機能しており、緊急度はやや低い。

---

### 5. 会議種別に応じたデバイス推奨 ★★☆

**根拠となるデータ**  
予約履歴には「全体会議」「レビュー」「採用面接」など会議種別が記録されている。  
会議の種類によって必要なデバイス（プロジェクター、Web会議機器、モニターなど）のニーズが異なる。

**提案内容**  
- 予約フォームで会議種別を選択した際、よく使われるデバイスをサジェストとして表示する
- 過去の貸出履歴と会議予約の日時を照合し、「この時間帯に一緒に借りられることが多いデバイス」を推奨する

**優先度が中の理由**  
貸出と予約のデータが現状連携していないため、実装には予約とデバイス貸出を紐づける設計変更が必要。段階的に実装できるが、初期コストがやや高い。

---

### 6. 利用レポートのエクスポート（CSV） ★☆☆

**根拠となるデータ**  
管理者が予約履歴・貸出履歴を外部で集計・報告する需要が想定される。現在はダッシュボードの閲覧のみ可能。

**提案内容**  
- 予約履歴・貸出履歴をCSV形式でダウンロードできるボタンをダッシュボードに追加する
- 期間フィルタ（月別など）を指定してエクスポートできるようにする

**優先度が低い理由**  
現状のダッシュボードでグラフによる傾向把握は可能。詳細な外部分析への需要は確認できるが、他の機能と比べて業務上の緊急性は低い。

---

### 7. 予約キャンセル待ちリスト ★☆☆

**根拠となるデータ**  
r004（20件）・r001（17件）・r007（16件）が特に利用頻度が高く、人気の部屋は取りづらい状況が生まれうる。

**提案内容**  
- 予約が埋まっている部屋・時間帯に対してキャンセル待ちを登録できる機能を追加する
- キャンセルが発生した際、待機者に通知する

**優先度が低い理由**  
部屋数が現状十分にあり（データ上 10室以上）、特定の部屋への集中は好みによるもので実際に取れない状況かは不明。需要が顕在化してから対応で十分。

---

## まとめ

最も即効性が高い機能は **定期予約** と **返却リマインダー** の 2つ。  
いずれも利用履歴から需要・リスクが直接確認できており、比較的シンプルな実装で大きな効果が見込める。
